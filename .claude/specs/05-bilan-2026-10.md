## 4. Le pipeline IA — état réel et plan pour la base ASSAD BENOIT

### Ce qui existe
- **Analyse** (`document-ingestion-service.ts`, prompts `lib/llm/analysis-prompt.ts`) : texte
  anonymisé (e-mails, téléphones, NIR seulement), tronqué à 60 000 caractères ; extraits de
  documents de **référence** (pgvector) ; descriptions d'images ; catalogue des critères du
  profil SAD. Sortie JSON, bloquée côté client par `analysisVisibleTo` jusqu'à relecture.
- **Génération** (`generateCorrectedDraft`) : Markdown → .docx brandé ; ne reçoit ni
  gabarit, ni exemple, ni descriptions d'images.

### Ce qui ne marche pas comme on le croit
1. **`DocumentTypeCriterion` est vide** → chaque analyse dit « aucun rattachement connu » ;
   les **guidelines de Sandrine par critère ne sont jamais injectées** ; la **pré-cotation**
   du module 3 ne se déclenche jamais. C'est le levier n°1 : le peupler débloque trois
   choses d'un coup (spec 04).
2. **Les gabarits ne sont ni indexés ni injectés** : `knowledge-indexing-service.ts` ne
   traite que les documents `REFERENCE`.
3. **Aucun mécanisme d'exemple validé** (few-shot / RAG sur des corrections) ; les
   suggestions de critères confirmées par Sandrine restent propres au document et ne
   remontent pas au type.
4. **Pas de jeu d'évaluation** (prévu 09 §6.3).
5. **Anonymisation insuffisante** pour des exemples : noms, adresses, raison sociale passent.

### Plan proposé (ordre de rendement)
1. **Peupler `DocumentTypeCriterion`** — écran admin + suggestions confirmées remontées au
   type. Débloque critères, guidelines, pré-cotation.
2. **Lien gabarit ↔ `DocumentType`** (n'existe pas).
3. **Indexer les gabarits `FINALE`** dans `KnowledgeChunk`, avec une colonne de nature pour
   ne jamais mélanger manuel HAS et exemples ; recherche filtrée par type de document.
4. **Bloc `<exemple_valide>`** dans `buildGenerationUserMessage` et dans l'analyse, traité
   comme donnée (même défense que `<document>`).
5. **Cahier de style** `context/10-regles-mise-en-conformite.md` versé dans le prompt système
   de génération (sommaire, numéros de page, encadré critères, références légales, champs
   `[À compléter]`, style court).
6. **Jeu d'évaluation** : paires « original → version validée » rejouées à chaque changement
   de prompt ou de modèle ; indicateur = taux de propositions acceptées sans correction.
7. **Génération qui préserve la mise en page** : partir du .docx d'origine (édition du XML)
   plutôt que de passer par Markdown — c'est ce qui permet aussi le surlignage vert.

**Contraintes** (détail `context/10` §9) : documents ASSAD jamais dans Git ; anonymisés avant
dépôt ; aucune pièce nominative ; cloisonnement par tenant ; fournisseur aligné sur D2.
